1. INTRODUCTION                                         *logpose-introduction*

logpose.nvim manages a markdown journal: daily notes, typed meeting notes,
a Kanban board of task files, weekly or sprint archives and reports, topic
notes with backlinks, and search across notes, tasks, tags, projects and
people.

Requires Neovim 0.10 or later.

==============================================================================
2. SETUP                                                       *logpose-setup*

`setup()` is optional; commands work with the defaults.
>lua
  require("logpose").setup({
    root = "~/path/to/journal",
  })
<
Options ~

  root           (string|nil)  Absolute path to the journal. `~` is expanded.
                 Overrides the journal saved by |:Logpose-init|.
  root_markers   (string[])    Markers that identify a journal root when
                 `root` is nil. Default: `{ ".logpose" }`.
  dirs           (table)       Paths relative to the root: `daily`,
                 `meetings`, `notes`, `projects`, `tasks`, `inbox`, `done`,
                 `journal_entries`, `done_entries`, `templates`, `reports`.
  affixes        (table)       Filename prefixes: `daily`, `week`,
                 `done_week`, `sprint` (""), `done_sprint` ("done-").
  link_style     ("wiki"|"markdown")  Link format. Default "wiki".
  workdays       (integer[])   ISO weekdays (Monday = 1). Default Mon-Fri.
                                                            *logpose-workdays*
  picker         (string)      "auto", "snacks", "fzf_lua", "telescope" or
                 "select". Default "auto".
  link_base      (string)      Directory (relative to root) that wiki-link
                 targets are relative to. Default "" (the root).
  meeting_filename (string)    Meeting filename without `.md`. Variables:
                 {date}, {time} (HHMM), {slug}, {type}. Must contain {slug}.
                 Default "{date} - {slug}".
  meeting_types  (table)       Meeting types by name. Fields: `label`,
                 `template` (default "meeting"), `order`, and either `title`
                 (fixed, no prompt) or `prompt` (asks; `title` may use
                 {input}). `person = true`: the input is a person (completed
                 from known people). `ask_attendees = true`: also ask for
                 attendees. Set a type to `false` to remove it.
  meeting_subdir (string)      Subdirectory of `dirs.meetings` for meeting
                 notes; `{project}` is the active project. "" keeps all
                 notes in one folder. Default "{project}".
  section_order  (string)      Order of `## YYYY-MM-DD` sections when logpose
                 inserts one: "auto" (follow the file), "newest_first" or
                 "oldest_first". Default "auto".
  archive        (table)       `journal_title`, `done_title`: title of a new
                 archive file; {period} is the period key (week start or
                 sprint name), {period_label} e.g. "week of 2026-10-05".
  period         (table)       How archives are grouped. `kind`: "week"
                 (default) or "sprint". `week_start`: ISO weekday weeks
                 start on (default 1, Monday). `sprint.anchor`: start date
                 of any one sprint (required for "sprint"; also enables
                 {sprint}); `sprint.length_days` (14); `sprint.first_number`
                 (number of the anchor sprint, 1); `sprint.name`
                 ("sprint-{n}"). Sprints are counted from the anchor in
                 both directions.
  me             (string|nil)  Your handle in action items, e.g. "@emmanuel".
  actions        (table)       `include_daily` (false): also collect daily
                 note tasks. `unassigned_mine` (true): items without an
                 owner count for `mine`. `output`: "quickfix" (default) or
                 "picker".
  series         (table)       `carry_over` (true): carry the previous
                 meeting's open tasks. `mark_carried` (true): mark them
                 `- [>]` in the previous note.
  standup        (table)       `sections` (names of the yesterday/today/
                 blockers headings), `carry_forward` (true), `mark_carried`
                 (true), `include_done` (false), `group_by_project` (true).
                 See |logpose-standup|.
  review         (table)       `stale_days` (14): open tasks older than this
                 are listed as stale in |:Logpose-report|.
  tickets        (table)       `pattern`: Lua pattern of ticket IDs
                 (default "%u[%u%d]+%-%d+", e.g. PROJ-123). `url`: URL with
                 {id}; when set, `gx` on a ticket in a journal note opens it.
  telemetry      (table)       `enabled` (false): count command use locally.
                 `retention_days` (180). See |:Logpose-stats|.
  views          (table)       Saved searches: name -> `find` arguments, e.g.
                 `{ acme = "tasks open project:acme" }`. See |:Logpose-view|.
  tasks          (table)       `mode`: "files" (default; one file per task,
                 see |logpose-board|) or "inbox" (INBOX.md/DONE.md checkboxes).
                 `capture_status` ("backlog") and `promote_status` ("todo"):
                 columns for |:Logpose-capture| and |:Logpose-promote|.
  board          (table)       `columns`: list of `{ key, label }` (default
                 Backlog, TODO, In progress, Follow-up, Done). `start`
                 ("in-progress") sets `started:`, `done` ("done") sets `done:`.
                 `done_window`: "period" (default) or a number of days of done
                 tasks to show. `min_column_width` (24): narrower, columns stack.
                 `stale_days` (7): cards this long in a column fade.
                 `collapsed` ({}): column keys folded when the board opens.
                 A column may set `limit` (WIP limit; In progress: 3) and `hl`.
  timestamps     (table)       `created` (true), `modified` (true): add
                 `created:`/`modified:` (local time, 2026-10-15T18:57) to new
                 notes. `modified:` is bumped when logpose changes a note and
                 when you save a changed one (only notes that have the key).
  search         (table)       `live` (true): with snacks, fzf-lua or
                 Telescope the picker prompt holds the query and results update
                 as you type. false: fixed results, fuzzy-filtered.
  retrieval      (table)       `sections`: headings whose every line is
                 searchable. Default decisions, blockers, risks, open
                 questions.
  projects       (table)       `detect` (boolean, default true): the git
                 repo of the current buffer/cwd is the project. `paths`
                 (table): directory -> project name; longest match wins.

Unknown options produce a warning; invalid values raise an error.

==============================================================================
3. JOURNAL ROOT                                                 *logpose-root*

The root is resolved in this order:

  1. The configured `root`.
  2. A marker above the current buffer's file.
  3. A marker above the current working directory.
  4. The journal saved by |:Logpose-init| (stored in
     `stdpath("data")/logpose/state.json`).

When none is found, commands offer to create a journal and then continue.

A bare `journal/` directory is not a marker.

4. COMMANDS                                                 *logpose-commands*

                                                                    *:Logpose*
:Logpose {subcommand} [args]
    Run a logpose subcommand. <Tab> completes subcommands and arguments.
    Without one, opens a menu of every command with its description and
    your keymap for it (most used first when usage stats are on).
    Each subcommand also has a `<Plug>(logpose-{subcommand})` mapping.
    A bang can go on the command or the subcommand: `:Logpose! archive` and
    `:Logpose archive!` are the same.
    No keymaps are set by default.

                                                               *:Logpose-init*
:Logpose init [{dir}]
    Choose or create the journal directory (prompts with `~/journal` when
    {dir} is omitted) and remember it. A new or empty directory gets
    `daily/`, `meetings/`, `INBOX.md`, `DONE.md` and the root marker; an
    existing one only gets the marker. Run again to switch journals.

                                                              *:Logpose-daily*
:Logpose daily [today|prev|next|{YYYY-MM-DD}]
    Create (from the `daily` template) and open a daily note. `prev` and
    `next` step by |logpose-workdays| from the daily note in the current
    buffer, or from today. An existing note is opened, never overwritten.

                                                            *:Logpose-meeting*
:Logpose meeting [{type}] [{YYYY-MM-DD}]
    Create a meeting note. Without {type}, choose from a list. Types with a
    `prompt` ask for input (a title, or a person for `1on1`). The note gets
    YAML frontmatter (type, date, title, attendees, series) and a link is
    added under `## Meetings` in that day's daily note. If the daily note
    has unsaved changes, the link is added to its buffer and left unsaved.

    Same type and title on the same day opens the existing note. With
    {time} in `meeting_filename`, you're asked whether to open the existing
    note or create a new one.

                                                            *:Logpose-archive*
:Logpose archive[!]
    Move done task files from before the current period into
    `dirs.tasks/archive/{period}/`, and `## YYYY-MM-DD` sections from before it (week or
    sprint, see `period`) out of `dirs.inbox` and `dirs.done` into one file
    per period in `dirs.journal_entries` and `dirs.done_entries`
    (`affixes.week` + the week's start date, or `affixes.sprint` + the
    sprint name). Existing week files are merged
    into: new dates are inserted in order, same dates get the body appended
    (unless it's already there, so re-running is safe). The preamble,
    current-week and non-date sections stay. A preview is shown first;
    with [!] it isn't. Nothing is written if any affected file has unsaved
    changes.

                                                            *:Logpose-capture*
:Logpose capture[!] [{text}]
    Create a task file in `tasks.capture_status` (Backlog) for the active
    project; `#tags` and `due:YYYY-MM-DD` in {text} go into the frontmatter.
    [!] opens the new file. Without {text}, prompts.
    With `tasks.mode = "inbox"`: add `- [ ] {text}` under today's section of
    `dirs.inbox` instead (tagged ` #project`; exact duplicates skipped).

                                                             *:Logpose-triage*
:Logpose triage [{filters}...]
    Open the board on the Backlog column. With `tasks.mode = "inbox"`:
    process open INBOX tasks one at a time, oldest first (items under
    `## Someday` are skipped). Actions: project, tag, due (relative dates
    accepted), owner (these keep the item), move (into a note's `## Action
    items` or `## Notes`), done, someday, drop (confirmed once per session),
    skip, quit. Filters as in |:Logpose-find|. Ends with a summary.

                                                               *:Logpose-done*
:[range]Logpose done
    In a task file (not on one of its checkboxes): move the task to Done.
    Otherwise mark the checkbox on the current line (or every one in
    [range]) done. `<Plug>(logpose-done)` also works in visual mode.
    With task files, checkboxes outside INBOX are only checked off. With
    `tasks.mode = "inbox"` (or in INBOX itself):
    In `dirs.inbox` the task is removed and added as `- [x] …` under today
    in `dirs.done`. In any other journal note it's checked off in place
    and logged in DONE with a link back to the note. Non-task lines are
    skipped. The current buffer is edited so |u| undoes it, then saved
    unless it already had unsaved changes.

                                                            *:Logpose-standup*
:Logpose standup [{date}]
    Show Yesterday / Today / Blockers of the daily note (today by default)
    in a scratch buffer, grouped by project tag. `q` closes it.

                                                            *logpose-standup*
Standup prep ~
A new daily note starts from the most recent earlier one: its checked
`## Today` tasks (and other lines) go under `## Yesterday`, its open tasks
move to the new `## Today` and are marked `- [>]` in the old note. Existing
notes are never changed.

                                                            *:Logpose-actions*
:Logpose actions [open|mine|overdue|all] [{filters}...]
    Action items (tasks) from meeting notes, in the quickfix list (or the
    picker, see `actions.output`). Default mode `open`. Tasks may carry
    `@owner` and `due:YYYY-MM-DD`; `mine` matches `me` (and unassigned
    items), `overdue` open items past their due date, `all` includes
    closed ones. Filters as in |:Logpose-find|.

                                                    *logpose-meeting-series*
Meeting series ~
A new meeting note whose `series` (type + title, or type + person for
prompted types, per project) has an earlier note gets `Previous: [[…]]` under
its title and a `## Carried over` section with that note's open tasks, which
are then marked `- [>]` (migrated) in the earlier note. See `series`.

                                                               *:Logpose-find*
:Logpose find [{scope}] [{filters}...]
    Search the journal and open the choice at its line. Uses snacks.picker,
    fzf-lua or Telescope (see `picker`), else |vim.ui.select|. Results
    preview the file at the line; `tags`, `projects` and `people` entries
    preview what they lead to.

    With `search.live`, the picker prompt starts with {filters} and the
    results are recomputed as you edit it. Unfinished filters (`project:`,
    `since:2026-1`) are ignored until complete.

    Scopes: `notes` (default), `daily`, `meetings`, `topics`, `archives`,
    `tasks`,
    `decisions`, `blockers` (lines under those `## ` headings), `people`,
    `tags` (choose a tag, then everything carrying it), `projects` (choose
    a project, then its notes and tasks).

    Filters (all must match):
      `project:{name}`   item's project, or a `#{name}` tag
      `#{tag}`, `tag:{tag}`  tagged
      `type:{type}`      meeting type
      `open`, `done`     tasks by state
      `since:{date}`, `until:{date}`  YYYY-MM-DD, today, yesterday,
                         tomorrow, -7d, +2w
      `week:{spec}`, `sprint:{spec}`  current, -N, +N, a date, or a
                         sprint number (sprints need `period.sprint.anchor`)
      `section:{name}`   under a `## ` heading containing {name}
      `status:{key}`     task files in that board column
      `blocked`          blocked task files
      `person:{name}`, `@{name}`  involves the person (attendee, 1:1,
                         @mention)
      other words        must all appear in the text

    Tags are inline `#words` (not headings, URL fragments or numbers such
    as `#123`) and frontmatter `tags:`, compared case-insensitively.

                                                               *:Logpose-grep*
:Logpose grep [{text}]
    Live grep in the journal with the picker plugin. Without one, searches
    for {text} (prompted if omitted) and opens the quickfix list.

                                                            *:Logpose-project*
:Logpose project [{name}|none]
    Pin the active project ({name} is slugified), or `none` to go back to
    auto-detection. Without an argument, pick from known projects.

    The active project is, in order: the pinned one, a `projects.paths`
    match, the git repo of the current buffer (or cwd), none. Inside the
    journal there is no project (unless pinned). With a project, meeting
    notes go to `meetings/{project}/`, get `project:` frontmatter, a
    project-scoped series and a `{project}: ` prefix on the daily link.

    `require("logpose").project()` returns the active project.

                                                         *logpose-statusline*
    `require("logpose").statusline({opts})` returns e.g.
    "acme · 2 in progress · 1 blocked · sprint-43 2/10": the active project,
    its cards in progress and blocked, and the workday of the current sprint
    or week. Cached (cheap on every redraw), refreshed when logpose changes
    anything. {opts}: `project`, `tasks`, `period` (booleans), `separator`.

                                                              *:Logpose-board*
:Logpose board [{filters}...]
    The task files as a Kanban board in the current window. See
    |logpose-board|.

                                                            *:Logpose-promote*
:Logpose promote
    Turn the checkbox on the cursor line into a task file in
    `tasks.promote_status` (TODO), with the note's project and a `From:`
    link, and replace the line's text with a link to the task.

                                                            *:Logpose-migrate*
:Logpose migrate[!]
    Turn open INBOX tasks into task files in Backlog (`due:` and `#tags` go
    to the frontmatter, a tag naming a known project becomes `project`, the
    section date `created`, indented lines the body, `## Someday` items get
    `#someday`) and remove them from INBOX. Preview first; [!] skips it.

                                                               *logpose-board*
Task files and the board ~
Each task is `dirs.tasks/{slug}.md` with frontmatter `title`, `status` (a
column key), `project`, `tags`, `due`, `blocked` (the reason), `created`,
`started`, `done` and an optional `order`, then free markdown and a `## Log`
that logpose appends to on every move. Keys on the board:

  h l / j k     previous / next column / card (cursor and mouse select too)
  H L  < >      move the card left / right      1-9   move it to column N
  x             done                            b     block / unblock
  <C-j> <C-k>   move the card down / up         a     add a card here
  K             peek at the task in a float     D     delete the card (asks first)
  z             fold / unfold the column        gg G  first / last card
  u             undo the last board change      <C-r> redo
  <CR>          open the task file              /     filter (find filters)
  p             this project / all              r     refresh
  q             close                           ?     help

Cards are boxes; the focused one has a heavy border. Each shows its days in
the column (from its log); cards older than `board.stale_days` fade. Column
headers show `count/limit` when a column has a `limit`, red above it. Columns
scroll on their own, keeping the focused card in view. The peek window (`K`)
is the task file itself: edit it, `q` closes and saves. Columns are coloured
through `LogposeBoardColumn1`… (linked to diagnostic groups; a column's `hl`
picks another group); other groups: `LogposeBoardFocus`, `LogposeBoardBlocked`,
`LogposeBoardOverdue`, `LogposeBoardProject`, `LogposeBoardTag`,
`LogposeBoardTitle`, `LogposeBoardHint`.

The board shows the active project's tasks (all when there is none); Done
shows tasks finished in `board.done_window`. Returning to the board buffer
redraws it. Standup, reports, archive, search (`status:`, `blocked`) and
health read task files too.

                                                               *:Logpose-view*
:Logpose view [{name}]
    Run the saved search {name} from `views` (choose one without {name}).

                                                               *:Logpose-note*
:Logpose note [{title}]
    Create (from the `note` template) or open `dirs.notes/{slug}.md`, a
    topic note not tied to a day. Prompts without {title}.

                                                       *:Logpose-project-page*
:Logpose project-page [{name}]
    Create (from the `project` template) or open `dirs.projects/{name}.md`.
    Defaults to the active project; otherwise choose one.

                                                          *:Logpose-backlinks*
:Logpose backlinks
    Notes and lines linking to the current note. Wiki links (also short
    `[[name]]`) and relative markdown links are understood.

                                                              *:Logpose-links*
:Logpose links
    Links going out of the current note; missing targets are flagged.

                                                         *logpose-completion*
Link completion ~
Typing `[[` in a journal note completes note links in `link_style`.
nvim-cmp: the `logpose` source is registered by `setup()`; add
`{ name = "logpose" }` to your markdown sources. blink.cmp: add the provider
`logpose = { name = "logpose", module = "logpose.completion.blink" }` and
`"logpose"` to your markdown sources.

                                                         *:Logpose-rename-tag*
:Logpose rename-tag[!] {old} {new}
    Rename inline `#old` tags and frontmatter `tags:` entries everywhere
    (whole tags only). Shows a preview and asks first; [!] skips it. Files
    with unsaved changes are never touched.

                                                     *:Logpose-rename-project*
:Logpose rename-project[!] {old} {new}
    Rename a project: `project:` frontmatter, `#old` tags, series names,
    `meetings/{old}/` and `projects/{old}.md` (moved), and links into
    them. Preview and [!] as for |:Logpose-rename-tag|.

                                                             *:Logpose-report*
:Logpose report[!] [week|sprint] [{offset}|{date}] [{filters}...]
    Summary of a period (default: the current one of `period.kind`; `-1`
    the previous; a date the period containing it) in a scratch buffer:
    DONE items, meetings, decisions, open action items, and a review
    section (overdue actions, stale tasks, aging and unassigned INBOX
    items). Filters as in |:Logpose-find|. With [!] it is saved to
    `dirs.reports/{period}.md`.

                                                             *:Logpose-ticket*
:Logpose ticket [{id}]
    Every line in the journal mentioning ticket {id} (default: the one
    under the cursor), whole word, in the quickfix list or picker.

                                                              *:Logpose-stats*
:Logpose stats[!] [{days}]
    Local usage stats when `telemetry.enabled` is set: uses per command
    (and scope for find, actions, report, daily), the last 7 days against
    the previous 7, errors, and unused commands. [!] resets them. Data
    lives in `stdpath("data")/logpose/usage.json` and holds only command
    names, keywords and daily counts.

==============================================================================
TEMPLATES                                                  *logpose-templates*

Templates are looked up in `<root>/<dirs.templates>/<name>.md`, then in the
plugin's `templates/` directory. Shipped: daily, meeting, planning,
refinement, review, retro, 1on1, note, project, task.

Variables: {date} {time} {weekday} {iso_week} {title} {type} {type_label}
{series} {attendees} {project} {sprint}. Unknown variables are left as is. {cursor} marks where
the cursor goes and is removed.

Notes logpose creates pass markdownlint's default rules: notes with a `title:`
in the frontmatter have no `# Title` heading (MD025), and blank lines around
headings, lists, tables and code blocks are kept when logpose creates or
reorganizes a note. Text you wrote is never rewrapped.

==============================================================================
5. HEALTH                                                     *logpose-health*

`:checkhealth logpose` reports the Neovim version, the resolved journal root
and how it was found, the active project, the archive period, which
journal paths exist, the picker in use and whether usage stats are on.
