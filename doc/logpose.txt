*logpose.txt*      A sprint journal: standup, meetings and a Kanban board

                                  LOGPOSE.NVIM

A standup that writes itself from what you did, meeting notes that remember
last time's action items, and a Kanban board where every task is a markdown
file.
Requires Neovim 0.10 or later.

1. INTRODUCTION                                         *logpose-introduction*

logpose manages a journal of plain markdown files in a folder you choose.
There is no database: it reads the structure you already write, which is
frontmatter, `## headings`, `#tags`, `@people` and `[[links]]`.

It is built around Scrum. It knows your sprints, so archives, reports and
search work sprint by sprint. It is also built for working on several
projects at once: the git repo you're in decides the project, and meetings,
tasks and the board are kept apart per project.

Every feature is a subcommand of |:Logpose|. Run `:Logpose` on its own for a
menu of all of them.

                                                            *logpose-concepts*
Tasks, notes and to-dos ~
logpose keeps three things apart, and every command, screen and search uses
these words:

  task    Work to get done: a file in `tasks/` with a status, project, tags
          and due date. It lives on the board (|logpose-board|).
  note    What you write down: daily notes, meeting notes, topic notes and
          project pages.
  to-do   A checkbox (`- [ ]`) inside a note: a reminder, or a meeting's
          action item. |:Logpose-check| checks it off.

|:Logpose-promote| moves things up a level, linking both ends: a to-do
becomes a task, and a task's write-up becomes a note.
The board counts the notes linked with each task (`✎ 2`); `n` opens them.

==============================================================================
2. QUICK START                                            *logpose-quickstart*

1. Create a journal: >vim
     :Logpose init
<   Accept `~/journal` or type another folder. logpose creates `daily/`,
   `meetings/` and `tasks/` and remembers the folder, so every command works
   from any buffer. A folder that already has notes only gets a `.logpose`
   marker file.

2. If you work in sprints, give logpose the start date and number of any
   one sprint (skip this if you work in weeks): >lua
     require("logpose").setup({
       period = {
         kind = "sprint",
         sprint = { anchor = "2026-10-15", first_number = 43 },
       },
     })
<
3. Start your day: >vim
     :Logpose daily
     :Logpose board
<
Then run `:checkhealth logpose` to see which journal, project and sprint
logpose sees.

A typical sprint ~

  Start of the day     `:Logpose today`: the standup, then what's due
  Before the standup   `y` on the today screen copies the standup
  Something comes up   `:Logpose capture Fix flaky test #ci`
  During the day       `:Logpose board`: `H`/`L` move a card, `x` finishes it
  In a meeting         `:Logpose meeting retro`
  After a meeting      `:Logpose promote` on an action item
  Sprint review        `:Logpose report sprint`
  New sprint           `:Logpose archive`

3. GUIDE                                                       *logpose-guide*

------------------------------------------------------------------------------
TODAY, STANDUP AND DAILY NOTES                               *logpose-standup*
                                                               *logpose-today*
|:Logpose-today| shows the day on one screen: the day and where it sits in
the sprint, then the standup, then what's coming up.

The standup is worked out from what happened, not from sections you fill in:

  Yesterday  since the previous workday (|logpose-workdays|; Friday on a
             Monday): tasks you moved or finished, from their `## Log`
             (`TODO → In progress`), the meetings you had, the to-dos you
             checked in your daily notes
  Today      tasks in progress or due, today's meetings, the open to-dos
             in today's daily note (or the ones it will carry over)
  Blockers   blocked tasks with their reasons, and the lines under
             `## Blockers` in the daily note

Coming up: tasks due in the next three days, overdue action items, and the
notes edited lately (the last five from the past week).

  <CR>  open the item at its line      y  copy the standup (markdown)
  d     daily note                     b  board
  r     refresh                        q  close

The copied standup is grouped by project (`standup.group_by_project`).
|:Logpose-standup| opens the screen on it; `:Logpose standup!` copies it.

                                                               *logpose-daily*
The daily note (|:Logpose-daily|) is a scratchpad for the day. Meetings link
themselves under `## Meetings`. A new note starts with what's still open
from the most recent one: its open to-dos, from anywhere in it, under
`## To-dos` (marked `- [>]` in the old note, so each lives in one place),
and the lines under `## Blockers`, which hold until you delete them.

Options: `daily` (`carry_over`, `mark_carried`), `standup`.

------------------------------------------------------------------------------
MEETINGS                                                    *logpose-meetings*

Meeting notes from a template, linked from your daily note.

|:Logpose-meeting| creates a note of one of these types:

  planning, refinement,   asks nothing; the title is fixed
  review, retro
  1on1                    asks for the person; titled "1:1 {person}"
  adhoc                   asks for a title

The note gets frontmatter (type, date, title, attendees, tags, series,
project) and a link under `## Meetings` in that day's daily note. Running the
same command again on the same day opens the existing note.

                                                         *logpose-new-meeting*
New-meeting form ~
`:Logpose meeting` without a type opens a form (the one of |logpose-edit|)
filled in as far as it can be: the first type, today's date (or the date
given), the active project. Fields: `type`, `title`, `date`, `project`,
`attendees`, `tags`. The title follows the type: empty gives the type's own
("Retro"), anything else replaces it; for a type that asks something, it's
the answer (a 1:1's person, completed from people; an ad-hoc title,
completed from past ones). Below the fields, what saving will do: the file
it creates, the daily-note link, what a series carries over. <C-s> creates
the note, closes the form and opens the note at the template's cursor; `q`
closes without creating anything. An existing note is opened, untouched.

                                                    *logpose-meeting-series*
Series ~
Meetings with the same type and title (or the same person, for 1:1s) form a
series within a project. A new note in a series starts with
`Previous: [[…]]` and a `## Carried over` section holding the previous note's
open to-dos. In the old note, those are marked `- [>]`.

Options: `meeting_types`, `meeting_filename`, `meeting_subdir`, `series`.

TASKS AND THE BOARD                                            *logpose-board*

Every task is a markdown file in `tasks/`, so it has room for context. The
board (|:Logpose-board|) is how you move them through the columns
Backlog, TODO, In progress, Follow-up and Done.

Each card shows its title, and under it `◆ project · due Tue ✎ 2 #tags`.
The project is in its own colour, picked from your colour scheme's palette
(a project page's `color:` wins); tags are chips on a soft background; the
rest is quiet. Colour is otherwise kept for what needs attention:
due dates read as words (`due Tue`, `due 3 Nov`; `due today`/`due tomorrow`
in yellow; `overdue 2d` in red); a blocked card has a red left edge and
reason (`⊘ waiting on Ana`); cards untouched for `board.stale_days` fade and
say `idle 9d` (blocked cards don't fade); done cards are dimmed, with a ✓.
The focused card has a heavy border and a background. On a one-project board
the project is left off the cards. When a card is narrow, the date stays
whole, the project name is shortened and tags are dropped. A column with a
`limit` (In progress: 3) shows `(2/3)` in its header, in red above the limit.

`✎ 2` counts the notes linked with the task: meeting, daily and other notes
that link to it, and notes it links to (like the `From:` link of a promoted
to-do). `n` opens them.

Columns scroll on their own, keeping the focused card in view. Narrow
windows stack the columns vertically. The board shows the active project's
tasks, or all of them when there is none (`p` switches). Done shows what
finished in the current week or sprint. Returning to the board buffer
redraws it. Keys: |logpose-board-keys|.

Task files ~
You never edit `status` by hand: logpose moves it, records `started` and
`done`, and appends a line to `## Log` on every change. >markdown
  ---
  title: "Fix flaky checkout test"
  status: in-progress
  project: acme
  tags: [ci]
  due: 2026-10-20
  blocked: waiting on ana
  created: 2026-10-15T09:05
  modified: 2026-10-16T15:02
  started: 2026-10-16
  done:
  ---
  ## Context

  Fails on Mondays only.

  ## Log

  - 2026-10-15 09:05: created in Backlog
  - 2026-10-16 09:10: TODO → In progress
<
An optional `order` key keeps the position you gave a card with
`<C-j>`/`<C-k>`.

Getting tasks in and out ~

  |:Logpose-capture|  from anywhere: a Backlog task for the active project
  `a` on the board    a card in the focused column
  |:Logpose-promote|  a to-do in a note becomes a Backlog task; in a task,
                      its write-up becomes a note (`N` on the board)
  |:Logpose-done|     in a task file: move it to Done
  `x` on the board    move the card to Done

To-dos aren't tasks: |:Logpose-check| checks them off.

                                                           *logpose-todo-sync*
A to-do made into a task and its task stay in step, both ways:

- The task done (`x` on the board, |:Logpose-done|, the form, or
  `status: done` saved by hand) checks its to-do, wherever it is (a to-do
  carried to a newer note keeps its `→` line).
- The to-do checked (|:Logpose-check|, or `[x]` saved by hand) moves the
  task to Done. When the task hasn't started (a column before
  `board.start`), you're asked first; say no and you aren't asked again
  for that task.
- Reopening: the task out of Done unchecks the to-do; the to-do unchecked
  moves the task back to the column it was in before Done.

Notes changed this way keep their `modified:` date; one with unsaved
changes is edited in its buffer. Board undo puts the to-do back too. A task
marked done outside Neovim still counts its to-do as done (in actions,
`find todos` and today).

Files with unsaved changes are never overwritten: logpose edits the buffer
instead, or refuses.

                                                     *logpose-board-highlight*
Colours ~
Each column header has a colour, linked to your colour scheme's diagnostic
groups, and each card's border takes its column's colour (`board.border`:
"project" tints it with the project's colour, "neutral" uses one quiet one).
A column's `hl` picks another group, or override these:
`LogposeBoardColumn1` … `LogposeBoardColumn5`, `LogposeBoardBorder`,
`LogposeBoardFocus`, `LogposeBoardFocusBg`, `LogposeBoardMeta`,
`LogposeBoardNotes`,
`LogposeBoardBlocked`, `LogposeBoardOverdue`, `LogposeBoardDueSoon`,
`LogposeBoardStale`, `LogposeBoardDone`, `LogposeBoardMarked`,
`LogposeBoardProject`, `LogposeBoardTag`, `LogposeBoardTitle`,
`LogposeBoardHint`.

Options: `board`, `tasks`.

------------------------------------------------------------------------------
MEETINGS, NOTES AND PEOPLE LISTS                               *logpose-lists*
                                                               *logpose-notes*
The board is for tasks; the lists are for everything else:

  |:Logpose-meetings|  every meeting: date, type, title, who was there, open
                     action items (`☐ 2 open`), tasks it led to (`→ 1 task`)
                     Group by week, type, project or series.
  |:Logpose-notes|     topic notes and project pages: date, title, open
                     to-dos, linked tasks, project, tags. Group by type,
                     project, tag or month. Daily notes show with
                     `type:daily` in the filter, meetings with
                     `type:meeting`.
  |:Logpose-people|    everyone you work with (|logpose-people|). Group by
                     page, project, role or when you last met.

Each shows the active project, or every project when there's none (a filter
given on the command line looks in every project). Every entry is listed:
scroll, or fold the groups you don't need (`z`).

Moving an entry to another group changes its note, so the list and the
files agree: another project moves a meeting to that project's folder (links
follow), another type sets its `type:`, another tag swaps the note's tag,
another project or role updates a person's page. Groups that come from the
note itself (week, month, last met) can't be moved to.

  <CR>    open (a heading: fold the group; a detail: open it)
  <Tab>   details: attendees, action items, linked tasks; for a person,
          their meetings, to-dos and mentions
  K       peek: the note in a floating window, to read and edit
  /       the filter bar (|logpose-filter-bar|)  <BS>  clear the filter
  g       change the grouping          s   change the order
  m       move to another group (asks; `new…` for a new project, tag or
          role)                        < >  to the previous / next group
  e       edit (|logpose-edit|)        a   add one, in the group you're in
  p       this project / all           z   fold the group
  ]] [[   next / previous group        r   refresh
  q       close                        ?   keys and filter cheat sheet

                                                          *logpose-filter-bar*
`/` on a list or the board opens a one-line filter over it; what's behind it
follows as you type. A menu shows what can come next, each with a word on
what it does: the filters (`type:`, `attendees:`, `date>=`, `or`, `not`, and
the fields your notes use), then their values from the journal (meeting
types, projects, tags, people, dates such as `today` or `-7d`). <Tab>
completes, <CR> keeps the filter, <Esc> restores the old one, <F1> shows the
cheat sheet. The lower edge counts the matches and names ignored words.

The notes list adds `d` (today's daily note) and `b` (the board); the people
list `y`, `o`, `t` and `R` (|logpose-people-screen|). `f` on a project in
|:Logpose-projects| opens its notes.

Highlights: `LogposeListTitle`, `LogposeListScope`, `LogposeListFilter`,
`LogposeListGroup`, `LogposeListCount`, `LogposeListTree`, `LogposeListDate`,
`LogposeListMeta`, `LogposeListTodos`, `LogposeListTasks`,
`LogposeListPeople`, `LogposeListHint`.

PROJECTS                                                    *logpose-projects*

One journal, many projects, kept apart automatically.

Switching ~
`:Logpose project` (or `P` on the board) opens the projects screen
(|:Logpose-projects|); <CR> on a project switches to it. `:Logpose project
{name}` switches directly; `auto` (or `c` on the screen) unpins and detects
the project again. Switching brings back the board on that project, as you
left it, and takes effect everywhere else at once. `projects.open_board =
false` stays where you are.

`:Logpose project none` (or `x` on the screen) means no project at all:
nothing is pinned or detected, and new meetings and topic notes open their
form with the project empty so you pick it per note (`:Logpose meeting
retro` opens the form with the type chosen). Every screen shows all
projects. It lasts, across restarts, until you switch or use `auto`.

The active project is, in order:

  1. the one pinned with |:Logpose-project|;
  2. a match in `projects.paths` (the longest match wins);
  3. a folder in a project page's `paths:` (|logpose-project-page|);
  4. the git repo of the current buffer, or of the current directory
     (`~/work/Acme API` becomes `acme-api`);
  5. none. Inside the journal itself there is no project, unless pinned.

With a project active, meeting notes go to `meetings/{project}/` with
`project:` in the frontmatter, series stay within the project, captured
tasks get the project, the board and statusline show its tasks, and the
daily-note link is prefixed with `{project}: `.
`require("logpose").project()` returns the active project.

                                                     *logpose-project-manager*
Managing projects ~
|:Logpose-projects| lists every project with what needs attention: open
tasks (and how many are in progress), overdue, due soon (within 3 days) and
blocked tasks, meetings, notes, and how long ago anything changed. The most
recently active come first; projects untouched for `review.stale_days` fade.
The active project is marked with `●`.

  <CR>   switch to the project; on a detail line, open that task or note
  <Tab>  show / hide what's going on in the project
  b      its board                     n  its project page
  t      its open tasks                f  its notes (|logpose-notes|)
  o      its open to-dos
  a      add a project (name, then repo folder)
  p      link another repo folder      R  rename it everywhere
  e      edit its name, description, repo folders and colour
  M      merge it into another one     c  detect the project (auto)
  x      no project (pick one per note)
  D      archive it                    U  restore an archived one
  A      show / hide archived          r  refresh
  q      close                         ?  help

                                                        *logpose-project-page*
Project pages ~
`projects/{name}.md` is where a project lives. The projects screen reads
its frontmatter, which you can edit by hand or with `e` there: >markdown
  ---
  title: "Acme API"
  project: acme
  description: Payments API for the Acme storefront
  paths: [~/work/acme-api, ~/work/acme-web]
  color: "#e0af68"
  ---
<
  `title`        the name you see (`project` is the short name)
  `description`  one line, shown on the projects screen
  `paths`        repo folders that belong to the project; working in one makes
                 it the active project
  `color`        hex colour or highlight group for its cards on the board
  `archived`     `true` when archived (|logpose-project-manager|)
  `merged_into`  set on a project merged into another

Moving tasks: `m` on the board, or `project` in the edit form
(|logpose-edit|), moves a task to another project. The move is logged, and
`u` on the board undoes it.

Merging (`M`, |:Logpose-merge-project|) moves one project's tasks, notes,
meetings (files and series) and links into another, with a preview. The old
project page stays, archived and marked `merged_into`, so links to it work.

Archiving sets `archived: true` in the project's page (creating the page if
needed). Its tasks and notes stay where they are and stay searchable, but it
leaves completion, the projects screen (until `A`) and the all-projects
board, and is unpinned if it was pinned. `U` restores it.

Known projects come from the pinned project, `projects.paths`, project pages,
meeting folders and the `project:` of any note or task.

Options: `projects`, `meeting_subdir`.

------------------------------------------------------------------------------
SEARCH                                                        *logpose-search*

|:Logpose-find| searches an index of every note, task, to-do and tagged
line, and opens the result at its line. The first word is the scope, the
rest are filters (|logpose-filters|), and every filter must match. >vim
  :Logpose find tasks open #perf
  :Logpose find todos open @ana
  :Logpose find decisions project:acme sprint:-1
  :Logpose find people
<
Scopes: `notes` (default; never lists tasks), `daily`, `meetings`, `topics`,
`tasks` (task files), `todos` (checkboxes in notes), `decisions`,
`blockers`, `tags` (pick a tag, then everything carrying it), `projects`
(pick one, then its notes, tasks and to-dos), `people`.

Live search: with snacks.nvim, fzf-lua or Telescope, the picker prompt holds
the query. It starts with the filters you typed and the results update as
you edit it. Half-typed filters (`project:`, `since:2026-1`) are ignored
until complete. Every result previews the file at its line; `tags`,
`projects` and `people` entries preview what they lead to. Without a picker
plugin, |vim.ui.select| is used.

Every line under `## Decisions`, `## Blockers`, `## Risks` and
`## Open questions` is searchable, tagged or not. That is what the
`decisions` and `blockers` scopes find.

Options: `search`, `retrieval`, `views`, `picker`.

------------------------------------------------------------------------------
ACTION ITEMS AND PEOPLE                                      *logpose-actions*

Action items are to-dos in meeting notes, optionally with an owner and a
due date: >markdown
  - [ ] Share load-test results @ana due:2026-10-21
<
|:Logpose-actions| lists them in the quickfix list, soonest due first, with
overdue items flagged. `mine` uses your `me` handle.

People come from meeting `attendees:`, the person of a 1:1, `@mentions`
and people pages (|logpose-people|). `:Logpose find people` lists everyone;
`@ana` or `person:ana` filters any search.

Options: `me`, `actions`.

------------------------------------------------------------------------------
PEOPLE PAGES                                                  *logpose-people*

A page per person you work with, `people/{slug}.md`: >markdown
  ---
  name: Ana López
  aliases: [Ana]
  role: Backend lead
  projects: [acme]
  email: ana@acme.com
  slack: ana.lopez
  ---
  Prefers async reviews. Back from leave on the 21st.
<
`aliases` make "Ana", `@ana` and "Ana López" one person: in completion,
in filters (`person:ana` also finds notes naming Ana López) and on the
people list. `projects` puts the person first in that project's meetings.
Add a person with `a` on the people list, |:Logpose-person|, or edit a
page with |:Logpose-edit|: the form has a field for each way to reach
people.

                                                       *logpose-people-screen*
|:Logpose-people| is one of the lists (|logpose-lists|): people with a page
(role, how to reach them, when you last met, the open to-dos they own),
then the people your notes mention who have no page yet. Besides the lists'
keys:

  <CR>    open their page (no page yet: the form to add one)
  a       add a person (on someone without a page: theirs); you stay
          on the list, on them, to add the next one
  t       talk: start a 1:1 with them (the first meeting type with
          `person`)
  y       copy a way to reach them    o   open it (mail, chat…)
  R       rename them everywhere (|:Logpose-rename-person|)

A bare first name with no page (`ana`) that only one fuller name starts with
(`Ana López`) says `same as Ana López? R merges`: `R` then offers that name,
and renaming makes them one person. You (`me`) aren't in the list.

`/` filters with any field too: `role:lead`, `slack:*`, `date>=-30d` (met
in the last 30 days).

`gx` on an `@mention`, or on a name in an `attendees:` or `with:` line,
opens that person's page when there is one.

                                                     *logpose-people-contacts*
Ways to reach people are configured (`people.contacts`), so another chat app
is a config change. Each key is a frontmatter key on the page: >lua
  people = {
    contacts = {
      email = { label = "Email", open = "mailto:{value}", order = 1 },
      slack = { label = "Slack", show = "@{value}", order = 2,
                open = "slack://user?team=T012345&id={value}" },
    },
  }
<
`label` names the field, `show` is how the value is shown, `open` is what
`o` opens (both with `{value}`), `order` sorts them. Email is the default.
Keys a page has that aren't configured still show, under their own name.

------------------------------------------------------------------------------
EDITING DETAILS                                                 *logpose-edit*

|:Logpose-edit| (or `e` on a board card, `e` on a project in
|:Logpose-projects|, or `:Logpose edit last` for the task captured last)
opens the frontmatter of a task or a note as a form in a floating window;
its title says which (`Edit task · …`, `Edit meeting · …`). Each line holds
one value; the field's name is drawn beside it and can't be edited. Lists
(`tags`, `attendees`, `paths`) are written `a, b`. Fields logpose keeps
itself (`created`, `modified`, `started`, `done`, `series`) are shown below.

As you type, a menu offers what fits the field: projects, board columns
(`status`), existing tags, people, meeting types, the next two weeks (`due`,
`date`) and folders (`paths`). In a list it completes the next item.
<C-x><C-o> also works.

Every value is checked as you type: a problem shows beside the field, a
valid value gets a note (what a date means, a project's name, "new project",
"new: Maria" for an attendee nobody has used yet), and an empty field shows
what to type. Below the fields, a summary says what
saving will do (set `started`, log a project change, move a meeting note and
fix N links to it). Nothing is saved while a field shows a problem.

  <Tab> <S-Tab>  open / move through the menu, or next / previous field
  <CR>           insert mode: accept from the menu (the highlighted item, or
                 the best match for what was typed), else next field;
                 normal mode: pick a value
  <C-a> <C-x>    next / previous status, project or type; dates: +1 / -1 day
  dd             clear the field          +      add a field
  <C-s>  :w      save; the form stays open, showing what was written
  q  <Esc>       close (normal mode); with unsaved changes, press twice
  :wq            save and close
  ?              show these keys in the form

Saving applies the changes the way logpose would:
  - a task's `status`, `project` and `blocked` go through the board's code:
    logged in the task, `started`/`done` kept; `u` on the board undoes an
    edit made there, one save at a time;
  - dates accept YYYY-MM-DD, `today`, `tomorrow`, a weekday (`fri`), `+3d`,
    `+1w`;
  - a meeting moved to another project moves into that project's folder,
    its `series` follows, and links to it (with the `- project:` label in
    daily notes) are fixed;
  - a project page's `project` can't change here: rename with `R` in
    |:Logpose-projects|.

A new task ~
`:Logpose capture` without text, or `a` on the board, opens the same form
for a task that doesn't exist yet: title (typed first), column, project,
tags, due date, blocker and `context` (a line under `## Context`). It starts
from the active project (on the board: the column, and the row with `s`).
Saving creates the task; the form then edits it, and on the board each save
is its own undo step.

Several tasks at once ~
Mark cards on the board with `v` and press `e`, or run `:'<,'>Logpose edit`
on lines of a quickfix list of tasks. Fields the tasks share start filled
in; the others start empty, meaning "leave each task as it is". In `tags`,
`+a -b` adds and removes tags (each task keeps its others); `none` clears a
project, due date or blocker.

------------------------------------------------------------------------------
TOPIC NOTES AND LINKS                                          *logpose-links*

Topic notes (|:Logpose-note|) hold knowledge that isn't tied to a day.
Project pages (|:Logpose-project-page|) are the hub for a project.
|:Logpose-backlinks| and |:Logpose-links| follow links in both directions.
Wiki links (`[[target|label]]`, or a short `[[name]]`) and relative markdown
links are understood. A wiki link's target is relative to the journal root
(`link_base`), not to the note, and may contain spaces.

                                                                  *logpose-gx*
`gx` in a journal note opens the note a wiki link points to, from anywhere
on the link. Everything else goes to the `gx` the buffer already had: a
markdown plugin's buffer mapping (which keeps markdown links, anchors and
URLs), or Neovim's (then logpose also follows markdown links to notes).
logpose maps `gx` after the other FileType handlers, so load order doesn't
matter.

                                                         *logpose-completion*
Completion in notes ~
In a journal note, `[[` offers every note and task to link (inserted in
`link_style`); a name in the frontmatter's `attendees:` or `with:` line
offers people; `@` in the text offers people as `@handle`.

  blink.cmp   add this provider, and `"logpose"` to your markdown sources:
    `logpose = { name = "logpose", module = "logpose.completion.blink" }`
  nvim-cmp    the source is registered by `setup()`; add
              `{ name = "logpose" }` to your markdown sources.

------------------------------------------------------------------------------
SPRINTS, ARCHIVES AND REPORTS                                *logpose-sprints*

Periods are Monday weeks unless you configure sprints. Give logpose the
start date and number of any one sprint and it counts the rest in both
directions: >lua
  period = {
    kind = "sprint",
    sprint = { anchor = "2026-10-15", length_days = 14, first_number = 43 },
  },
<
This drives the `sprint:` filters, the `{sprint}` template variable, the
board's Done column, the statusline, |:Logpose-report| and
|:Logpose-archive|. To align weeks with Thursday sprints instead, use
`period = { week_start = 4 }`.

------------------------------------------------------------------------------
STATUSLINE                                                *logpose-statusline*

`require("logpose").statusline({opts})` returns e.g.
"acme · 2 in progress · 1 blocked · sprint-43 2/10": the active project, its
cards in progress and blocked, and the workday of the current sprint or
week. It is cached, so it's cheap to call on every redraw, and refreshes
when logpose changes anything. For lualine: >lua
  sections = {
    lualine_x = { function() return require("logpose").statusline() end },
  }
<
{opts}: `project`, `tasks`, `period` (booleans, default true) and
`separator` (default " · ").

4. COMMANDS                                                 *logpose-commands*

                                                                    *:Logpose*
:Logpose [{subcommand}] [args]
    Run a subcommand. <Tab> completes subcommands and arguments. Without
    one, opens a menu of every command, with what it does and your keymap
    for it (most used first when usage stats are on).

    Each subcommand has a `<Plug>(logpose-{subcommand})` mapping. A bang can
    go on either word: `:Logpose! archive` is `:Logpose archive!`.

Daily work ~

                                                              *:Logpose-today*
:Logpose today
    The day at a glance: the standup, then what's coming up. See
    |logpose-today|.

                                                              *:Logpose-daily*
:Logpose daily [{day}]
    Open the daily note for {day}: `today` (default), `prev`, `next` or a
    date (YYYY-MM-DD), creating it from the `daily` template and the
    previous note's open to-dos and blockers (|logpose-daily|). `prev` and `next` step by
    |logpose-workdays| from the daily note in the current buffer, or from
    today. An existing note is opened, never overwritten.

                                                            *:Logpose-standup*
:Logpose standup[!] [{date}]
    The today screen, on the standup (|logpose-standup|). With [!], copy
    it as markdown instead. With {date}, that day's standup in a scratch
    buffer.

                                                            *:Logpose-meeting*
:Logpose meeting [{type}] [{YYYY-MM-DD}]
    Create a meeting note (|logpose-meetings|). Without {type}, the
    new-meeting form (|logpose-new-meeting|). A date backfills a note for
    that day. If the daily note has
    unsaved changes, the link is added to its buffer and left unsaved.
    With {time} in `meeting_filename`, you're asked whether to open the
    existing note or create a new one.

Tasks ~

                                                              *:Logpose-board*
:Logpose board [{filters}...]
    The Kanban board in the current window (or a tab, see `board.open`).
    {filters} as in |logpose-filters|. See |logpose-board|.

                                                            *:Logpose-capture*
:Logpose capture[!] [{text}]
    Create a task in `tasks.capture_status` (Backlog) for the active
    project, or the one named with `+name` in {text} (`+none`: no project).
    `#tags` and `due:` (a date, `today`, `tomorrow`, `fri`, `+3d`) go into
    the frontmatter. <Tab> completes `+projects`, `#tags` and `due:`. The
    message after it names the project and how it was chosen; |:Logpose-edit|
    `last` fixes a wrong one. [!] opens the new file. Without {text}: the
    new-task form (|logpose-edit|), to set the title, column, project, tags,
    due date, blocker and a line of context before the task exists.

                                                               *:Logpose-done*
:Logpose done
    Move the task you're in (its task file) to Done. Anywhere else it says
    so: a to-do is checked off with |:Logpose-check|.

To-dos ~

                                                              *:Logpose-check*
:[range]Logpose check
    Check off the to-do (`- [ ]`) on the current line, or every one in
    [range]; when they're all checked already, uncheck them. Other lines
    are skipped. `<Plug>(logpose-check)` works in visual mode too. The buffer
    is edited, so |u| undoes it. A to-do made into a task brings its task
    along (|logpose-todo-sync|).

                                                            *:Logpose-promote*
:[range]Logpose promote
    Move something up a level, linking both ends to each other.

    On a to-do: a task in `tasks.promote_status` (Backlog; Done if it was
    checked), with the note's project and a `From:` link back. The to-do
    keeps its text (an action item its owner and due date) and gains a
    `→ [[task]]` line under it. The two then stay in step
    (|logpose-todo-sync|).

    In a task file (not on one of its to-dos), or on [range] there: the
    new-note form, filled in from the task (title, project, tags) with a
    `content` field: `copy` (default) keeps the write-up in the task, `move`
    leaves only the link there. The write-up is the body without `## Log`,
    `## Notes` and the task's `From:` line, or the lines in [range]. The note
    starts with `From: [[task]]`; the task gets the note under `## Notes`. A
    note with that title gets the write-up added at its end. `N` on the
    board does the same for the focused card.

                                                            *:Logpose-actions*
:Logpose actions [{mode}] [{filters}...]
    Action items: to-dos in meeting notes (|logpose-actions|), in the
    quickfix list, or the picker with `actions.output = "picker"`. {mode}:
      `open`     open items (default)
      `mine`     yours (`me`), plus unassigned ones with
                 `actions.unassigned_mine`
      `overdue`  open and past their due date
      `all`      closed ones too

Finding things ~

                                                               *:Logpose-find*
:Logpose find [{scope}] [{filters}...]
    Search the journal. See |logpose-search| and |logpose-filters|.

                                                               *:Logpose-grep*
:Logpose grep [{text}]
    Live grep in the journal with the picker plugin. Without one, searches
    for {text} (prompted if omitted) into the quickfix list.

                                                               *:Logpose-view*
:Logpose view [{name}]
    Run the saved search {name} from `views`. Without {name}, choose one.

                                                             *:Logpose-ticket*
:Logpose ticket [{id}]
    Every line mentioning ticket {id} (default: the one under the cursor),
    as a whole word. With `tickets.url` set, `gx` on a ticket in a journal
    note opens it (|logpose-gx|).

                                                          *:Logpose-backlinks*
:Logpose backlinks
    Notes and lines linking to the current note.

                                                              *:Logpose-links*
:Logpose links
    Links going out of the current note. Missing targets are flagged.

Notes and projects ~

                                                           *:Logpose-meetings*
:Logpose meetings [{filters}...]
    The meetings list (|logpose-lists|), starting with {filters}
    (|logpose-filters|).

                                                              *:Logpose-notes*
:Logpose notes [{filters}...]
    The notes list (|logpose-lists|), starting with {filters}.

                                                               *:Logpose-note*
:Logpose note [{title}]
    Create (from the `note` template) or open `notes/{slug}.md`. Without
    {title}, a form (|logpose-edit|) for its title, project and tags; <C-s>
    creates the note and opens it.

                                                               *:Logpose-edit*
:Logpose edit [last]
:[range]Logpose edit
    Edit the frontmatter of the current task or note in a form. With
    `last`, or when the current buffer isn't in the journal, the task
    captured last in this session. In a quickfix window, the tasks on the
    [range] of lines, together. See |logpose-edit|.

                                                             *:Logpose-people*
:Logpose people [{filters}...]
    The people list (|logpose-people-screen|), starting with {filters}.

                                                             *:Logpose-person*
:Logpose person [{handle}]
    Open the page of the person {handle} names (a name, alias or handle;
    completion offers handles). Without a page, or without {handle}, the
    form to add one.

                                                            *:Logpose-project*
:Logpose project [{name}|none|auto]
    Switch to project {name} ({name} is slugified); `none` for no project
    (you pick one per note); `auto` to detect it again
    (|logpose-projects|). Without an argument, opens the projects
    screen (|:Logpose-projects|).

                                                           *:Logpose-projects*
:Logpose projects
    The project manager: switch, add, rename, archive and restore projects.
    See |logpose-project-manager|.

                                                       *:Logpose-project-page*
:Logpose project-page [{name}]
    Create (from the `project` template) or open `projects/{name}.md`.
    Defaults to the active project; otherwise choose one.

Sprints and maintenance ~

                                                             *:Logpose-report*
:Logpose report[!] [week|sprint] [{offset}|{date}] [{filters}...]
    Summary of a period in a scratch buffer. Default: the current period of
    `period.kind`; `-1` the previous one; a date the period containing it.
    Lists tasks done, meetings, decisions and open action items, then a
    review section: overdue actions per project, open to-dos older than
    `review.stale_days`, blocked tasks, and tasks in progress for longer.
    [!] saves it to `reports/{period}.md`.

                                                            *:Logpose-archive*
:Logpose archive[!]
    Move done tasks from before the current period off the board, to
    `tasks/archive/{period}/`, where reports and search still find them.
    Running it again is safe. Shows a preview first; [!] skips it. Nothing
    is moved if one of the tasks has unsaved changes.

                                                      *:Logpose-merge-project*
:Logpose merge-project[!] {old} {new}
    Merge project {old} into the existing project {new}: `project:`
    frontmatter, `#old` tags, series names, meeting files and links. The
    old project page stays, archived with `merged_into: {new}`. Preview and
    [!] as for |:Logpose-rename-tag|.

                                                         *:Logpose-rename-tag*
:Logpose rename-tag[!] {old} {new}
    Rename inline `#old` tags and frontmatter `tags:` entries everywhere
    (whole tags only: not `#oldest`; code blocks are left alone). Shows a
    preview and asks first; [!] skips it. Files with unsaved changes are
    never touched.

                                                     *:Logpose-rename-project*
:Logpose rename-project[!] {old} {new}
    Rename a project: `project:` frontmatter, `#old` tags, series names,
    `meetings/{old}/` and `projects/{old}.md` (moved), and links into them,
    short `[[{old}]]` ones too when the name is unique. Open buffers follow
    the files they move. Preview and [!] as for |:Logpose-rename-tag|.

                                                      *:Logpose-rename-person*
:Logpose rename-person[!] {handle} [{new name}]
    Rename a person everywhere: their page moves to `people/{new-slug}.md`
    (links follow) and keeps the old name in `aliases`; `attendees:` and
    `with:` entries and `@mentions` using the old name are rewritten.
    Without {new name}, asks for it. Preview and [!] as for
    |:Logpose-rename-tag|.

                                                               *:Logpose-init*
:Logpose init [{dir}]
    Choose or create the journal folder (prompts with `~/journal` when
    {dir} is omitted) and remember it. A new or empty folder gets `daily/`,
    `meetings/`, `tasks/` and the `.logpose` marker. An existing one only
    gets the marker. Run it again to switch journals.

                                                              *:Logpose-stats*
:Logpose stats[!] [{days}]
    Local usage stats (on unless `telemetry.enabled = false`): uses per
    command (and scope for find, actions, report and daily), the last 7 days
    against the previous 7, errors, and commands you haven't used. [!]
    resets them.
    Data lives in `stdpath("data")/logpose/usage.json` and holds only
    command names, keywords and daily counts, never note content or paths.

6. SEARCH FILTERS                                            *logpose-filters*

Used by |:Logpose-find|, |:Logpose-board|, the lists (|logpose-lists|),
|:Logpose-actions| and |:Logpose-report|. Filters next to each other must all
match; `or` gives either one (`and` binds tighter), `not` or a leading `-`
the opposite (also of a group: `-(a or b)`), and parentheses group: >
  (type:retro or type:review) @ana -#draft
<
  project:{name}          the item's project, or a `#{name}` tag
  #{tag}  tag:{tag}       tagged items
  @{name}  person:{name}  involves the person (attendee, 1:1, @mention),
                          under any of their names
  type:{type}             meetings of that type; or the kind of note:
                          daily, meeting, topic, project, task, person
  open  done              tasks (in Done or not), to-dos (checked or not)
  status:{key}            tasks in that board column
  blocked                 blocked tasks
  since:{date}            on or after; YYYY-MM-DD, today, yesterday,
  until:{date}            tomorrow, -7d, +2w
  week:{spec}             a whole week or sprint: current, -N, +N, a date,
  sprint:{spec}           or a sprint number (needs `period.sprint.anchor`)
  section:{name}          lines under a `## ` heading containing {name}
  {key}:{value}           any frontmatter field containing {value} (case
                          and accents ignored): `room:lisboa`, `role:lead`
  attendees:{name}        meetings with the person, by any of their names
  with:{name}             or part of one
  date:{when}             a day, month (2026-10) or year; also `due:`,
                          `created:`, `started:`, `done:`, `modified:`
  {key}>={v}  {key}>{v}   comparisons, for dates (`date>=-7d`, `due<today`)
  {key}<={v}  {key}<{v}   and numbers (outside date fields, `score>=2000`
                          is a number, not a year)
  date:{a}..{b}           a range of dates (`date:..2026-09` from the start)
  {key}:*  has:{key}      has the field
  no:{key}                doesn't
  "two words"             a value with spaces: `attendees:"Ana López"`
  other words             must all appear in the text (accents ignored)

Tags are inline `#words` (not headings, URL fragments, numbers such as
`#123` or anything in a code block) and frontmatter `tags:` (a `[a, b]` list
or a block list), compared without case. Accented words count whole:
`#reunión`, `@José`.

8. CONFIGURATION                                               *logpose-setup*

`setup()` is optional; every command works with the defaults. >lua
  require("logpose").setup({
    period = { kind = "sprint", sprint = { anchor = "2026-10-15" } },
    me = "@ana",
    keymaps = true,
  })
<
Unknown options produce a warning; invalid values raise an error. Lists
replace the default rather than merging with it.

General ~

  root           (string|nil)  Journal path (`~` is expanded). Overrides
                 the journal chosen with |:Logpose-init|.
  me             (string|nil)  Your handle in action items, e.g. "@ana".
  keymaps        (boolean|table)  false. See |logpose-keymaps|.
                                                            *logpose-workdays*
  workdays       (integer[])   ISO weekdays you work (Monday = 1).
                 Default Monday to Friday. Used by `daily prev/next`, the
                 standup and the sprint day count.
  picker         (string)      "auto" (default), "snacks", "fzf_lua",
                 "telescope" or "select".
  link_style     ("wiki"|"markdown")  Format of links logpose writes.
                 Default "wiki".
  projects       (table)       `detect` (true): the git repo of the current
                 buffer or directory is the project. `paths` ({}): folder ->
                 project name; the longest match wins. `open_board` (true):
                 switching project opens its board.

Sprints and periods ~

  period         (table)       `kind`: "week" (default) or "sprint".
                 `week_start`: ISO weekday weeks start on (1, Monday).
                 `sprint.anchor`: start date of any one sprint (required
                 for "sprint"; also enables {sprint}).
                 `sprint.length_days` (14). `sprint.first_number` (number
                 of the anchor sprint, 1). `sprint.name` ("sprint-{n}").
  review         (table)       `stale_days` (14): in |:Logpose-report|,
                 open to-dos older than this, and tasks in progress longer,
                 are flagged.

Board and tasks ~

  board          (table)
      `columns`           list of `{ key, label, limit?, hl? }`. Default
                          Backlog, TODO, In progress (limit 3), Follow-up,
                          Done. `limit` is a WIP limit; `hl` a highlight
                          group for the column's colour.
      `start`             column that records `started:` ("in-progress")
      `done`              column that records `done:` ("done")
      `done_window`       "period" (default: the current week or sprint)
                          or a number of days of done tasks to show
      `min_column_width`  below this, columns stack vertically (24)
      `stale_days`        cards untouched this long fade and say "idle" (7)
      `border`            "column" (default: card borders in their
                          column's colour), "project" or "neutral"
      `collapsed`         column keys folded when the board opens ({})
      `icons`             "unicode" (default), "nerd" or "ascii"
      `compact`           start with one-line cards (false)
      `lanes`             start with one row per project (false)
      `open`              "window" (default) or "tab"
  tasks          (table)
      `capture_status`    column for |:Logpose-capture| ("backlog")
      `promote_status`    column for |:Logpose-promote| ("backlog")

Notes and meetings ~

  meeting_types  (table)       Types by name. Fields: `label`, `template`
                 (default "meeting"), `order`, and either `title` (fixed)
                 or `prompt` (asks; `title` may use {input}).
                 `person = true`: the input is a person, completed from
                 known people. `ask_attendees = true`: also ask for
                 attendees. Set a type to `false` to remove it.
  meeting_filename (string)    Without `.md`. Variables: {date}, {time}
                 (HHMM), {slug}, {type}. Must contain {slug}.
                 Default "{date} - {slug}".
  meeting_subdir (string)      Subfolder of `meetings/`; {project} is the
                 active project. "" keeps all notes in one folder.
                 Default "{project}".
  series         (table)       `carry_over` (true): carry the previous
                 meeting's open to-dos. `mark_carried` (true): mark
                 them `- [>]` in the previous note.
  daily          (table)       `carry_over` (true): a new daily note
                 starts with the previous one's open to-dos and blockers.
                 `mark_carried` (true): mark carried to-dos `- [>]`.
  standup        (table)       `group_by_project` (true): group the
                 copied standup by project.
  timestamps     (table)       `created` (true), `modified` (true): add
                 `created:` and `modified:` (local time, 2026-10-15T18:57)
                 to new notes. `modified:` is bumped when logpose changes a
                 note and when you save a changed one; only notes that have
                 the key are touched.

Search and action items ~

  search         (table)       `live` (true): the picker prompt holds the
                 query and results update as you type. false: fixed
                 results that the picker fuzzy-filters.
  retrieval      (table)       `sections`: headings whose every line is
                 searchable. Default decisions, blockers, risks, open
                 questions.
  views          (table)       Saved searches: name -> `find` arguments,
                 e.g. `{ acme = "tasks open project:acme" }`.
  people         (table)       `contacts`: ways to reach people, key ->
                 `{ label, show, open, order }` (|logpose-people-contacts|).
                 Default: `email` only.
  actions        (table)       `include_daily` (false): also collect daily
                 note to-dos. `unassigned_mine` (true): items without
                 an owner count for `mine`. `output`: "quickfix" (default)
                 or "picker".
  tickets        (table)       `pattern`: Lua pattern of ticket IDs
                 (default "%u[%u%d]+%-%d+", e.g. PROJ-123). `url`: URL with
                 {id}; when set, `gx` on a ticket opens it.
  telemetry      (table)       `enabled` (true): count command use
                 locally. `retention_days` (180). See |:Logpose-stats|.

Folders and file names ~

  root_markers   (string[])    Files that mark a journal root.
                 Default `{ ".logpose" }`.
  dirs           (table)       Paths relative to the root: `daily`,
                 `meetings`, `notes`, `projects`, `tasks`, `people`,
                 `templates`, `reports`.
  affixes        (table)       Prefixes: `daily` ("daily-") for daily
                 notes; `week` ("week-") and `sprint` ("") for the folders
                 in `tasks/archive/`.
  link_base      (string)      Folder (relative to the root) that wiki-link
                 targets are relative to. Default "" (the root).

9. TEMPLATES                                               *logpose-templates*

Templates are looked up in your journal's `templates/` folder first, then in
the plugin's. Shipped: daily, meeting, planning, refinement, review, retro,
1on1, note, project, task.

  {date} {time} {weekday}     2026-10-15, 09:05, Thursday
  {iso_week} {sprint}         2026-W42, sprint-43
  {title} {type} {type_label} the note's title and meeting type
  {project} {series}          the active project and meeting series
  {attendees}                 the meeting's attendees
  {cursor}                    where the cursor lands (removed)

Unknown variables are left as they are.

Notes logpose creates pass markdownlint's default rules. Notes with a
`title:` in the frontmatter have no `# Title` heading, because markdownlint
counts the frontmatter title as the top heading (MD025). logpose keeps blank
lines around the headings, lists, tables and code blocks it inserts, and
never rewraps text you wrote.

10. JOURNAL ROOT AND LAYOUT                                     *logpose-root*

The journal root is resolved in this order:

  1. The configured `root`.
  2. A `.logpose` marker above the current buffer's file.
  3. A marker above the current working directory.
  4. The journal saved by |:Logpose-init| (in
     `stdpath("data")/logpose/state.json`).

When none is found, commands offer to create a journal and then continue.

                                                              *logpose-layout*
Layout ~
>
  ~/journal/
  ├── .logpose                       marks the journal root
  ├── daily/daily-2026-10-15.md      notes: daily,
  ├── meetings/acme/2026-10-14 - retro.md       meetings,
  ├── notes/queue-design.md                     topic notes,
  ├── projects/acme.md                          project pages
  ├── people/ana-lopez.md            people pages
  ├── tasks/fix-flaky-test.md        tasks: one file each
  ├── tasks/archive/sprint-42/       done tasks from past sprints
  ├── reports/sprint-42.md
  └── templates/                     your template overrides
<
To-dos (checkboxes in notes): `- [ ]` open, `- [x]` checked, `- [>]`
carried to a newer note.

11. HEALTH AND TROUBLESHOOTING                                *logpose-health*

`:checkhealth logpose` reports the Neovim version, the journal root and how
it was found, the active project, the current week or sprint, which journal
folders exist, the picker in use and whether usage stats are on.

  Wrong project, or an empty board: check the active project in the health
  report. `:Logpose project auto` unpins a project; `p` on the board
  shows all projects.

  A file wasn't changed: logpose never overwrites a file with unsaved
  changes. It edits the open buffer instead, or refuses and says so. Writes
  are atomic: a failed save (a full disk) leaves the old file as it was, and
  a symlinked note is written through to its target.

  "state.json couldn't be read": the saved state (the journal from
  |:Logpose-init|, recent projects) was corrupt. It was moved to
  `state.json.bad` next to it; run |:Logpose-init| again.
