1. INTRODUCTION                                         *logpose-introduction*

logpose.nvim manages a markdown journal: daily notes, typed meeting notes,
an INBOX/DONE Kanban flow and weekly or sprint archives.

Requires Neovim 0.10 or later.

==============================================================================
2. SETUP                                                       *logpose-setup*

`setup()` is optional; commands work with the defaults.
>lua
  require("logpose").setup({
    root = "~/path/to/journal",
  })
<
Options ~

  root           (string|nil)  Absolute path to the journal. `~` is expanded.
                 Overrides the journal saved by |:Logpose-init|.
  root_markers   (string[])    Markers that identify a journal root when
                 `root` is nil. Default: `{ ".logpose" }`.
  dirs           (table)       Paths relative to the root: `daily`,
                 `meetings`, `inbox`, `done`, `journal_entries`,
                 `done_entries`, `templates`, `reports`.
  affixes        (table)       Filename prefixes: `daily`, `week`,
                 `done_week`, `sprint` (""), `done_sprint` ("done-").
  link_style     ("wiki"|"markdown")  Link format. Default "wiki".
  workdays       (integer[])   ISO weekdays (Monday = 1). Default Mon-Fri.
                                                            *logpose-workdays*
  picker         (string)      "auto", "snacks", "fzf_lua", "telescope" or
                 "select". Default "auto".
  link_base      (string)      Directory (relative to root) that wiki-link
                 targets are relative to. Default "" (the root).
  meeting_filename (string)    Meeting filename without `.md`. Variables:
                 {date}, {time} (HHMM), {slug}, {type}. Must contain {slug}.
                 Default "{date} - {slug}".
  meeting_types  (table)       Meeting types by name. Fields: `label`,
                 `template` (default "meeting"), `order`, and either `title`
                 (fixed, no prompt) or `prompt` (asks; `title` may use
                 {input}). Set a type to `false` to remove it.
  meeting_subdir (string)      Subdirectory of `dirs.meetings` for meeting
                 notes; `{project}` is the active project. "" keeps all
                 notes in one folder. Default "{project}".
  section_order  (string)      Order of `## YYYY-MM-DD` sections when logpose
                 inserts one: "auto" (follow the file), "newest_first" or
                 "oldest_first". Default "auto".
  archive        (table)       `journal_title`, `done_title`: title of a new
                 archive file; {period} is the period key (week start or
                 sprint name), {period_label} e.g. "week of 2026-10-05".
  period         (table)       How archives are grouped. `kind`: "week"
                 (default) or "sprint". `week_start`: ISO weekday weeks
                 start on (default 1, Monday). `sprint.anchor`: start date
                 of any one sprint (required for "sprint"; also enables
                 {sprint}); `sprint.length_days` (14); `sprint.first_number`
                 (number of the anchor sprint, 1); `sprint.name`
                 ("sprint-{n}"). Sprints are counted from the anchor in
                 both directions.
  projects       (table)       `detect` (boolean, default true): the git
                 repo of the current buffer/cwd is the project. `paths`
                 (table): directory -> project name; longest match wins.

Unknown options produce a warning; invalid values raise an error.

3. JOURNAL ROOT                                                 *logpose-root*

The root is resolved in this order:

  1. The configured `root`.
  2. A marker above the current buffer's file.
  3. A marker above the current working directory.
  4. The journal saved by |:Logpose-init| (stored in
     `stdpath("data")/logpose/state.json`).

When none is found, commands offer to create a journal and then continue.

A bare `journal/` directory is not a marker.

4. COMMANDS                                                 *logpose-commands*

                                                                    *:Logpose*
:Logpose {subcommand} [args]
    Run a logpose subcommand. <Tab> completes subcommands and arguments.
    Each subcommand also has a `<Plug>(logpose-{subcommand})` mapping.
    A bang can go on the command or the subcommand: `:Logpose! archive` and
    `:Logpose archive!` are the same.
    No keymaps are set by default.

                                                               *:Logpose-init*
:Logpose init [{dir}]
    Choose or create the journal directory (prompts with `~/journal` when
    {dir} is omitted) and remember it. A new or empty directory gets
    `daily/`, `meetings/`, `INBOX.md`, `DONE.md` and the root marker; an
    existing one only gets the marker. Run again to switch journals.

                                                              *:Logpose-daily*
:Logpose daily [today|prev|next|{YYYY-MM-DD}]
    Create (from the `daily` template) and open a daily note. `prev` and
    `next` step by |logpose-workdays| from the daily note in the current
    buffer, or from today. An existing note is opened, never overwritten.

                                                            *:Logpose-meeting*
:Logpose meeting [{type}] [{YYYY-MM-DD}]
    Create a meeting note. Without {type}, choose from a list. Types with a
    `prompt` ask for input (a title, or a person for `1on1`). The note gets
    YAML frontmatter (type, date, title, attendees, series) and a link is
    added under `## Meetings` in that day's daily note. If the daily note
    has unsaved changes, the link is added to its buffer and left unsaved.

    Same type and title on the same day opens the existing note. With
    {time} in `meeting_filename`, you're asked whether to open the existing
    note or create a new one.

                                                            *:Logpose-archive*
:Logpose archive[!]
    Move `## YYYY-MM-DD` sections from before the current period (week or
    sprint, see `period`) out of `dirs.inbox` and `dirs.done` into one file
    per period in `dirs.journal_entries` and `dirs.done_entries`
    (`affixes.week` + the week's start date, or `affixes.sprint` + the
    sprint name). Existing week files are merged
    into: new dates are inserted in order, same dates get the body appended
    (unless it's already there, so re-running is safe). The preamble,
    current-week and non-date sections stay. A preview is shown first;
    with [!] it isn't. Nothing is written if any affected file has unsaved
    changes.

                                                            *:Logpose-capture*
:Logpose capture [{text}]
    Add `- [ ] {text}` under today's `## YYYY-MM-DD` section of `dirs.inbox`
    (created if needed, placed per `section_order`). With an active
    project, ` #project` is appended. Without {text}, prompts. An exact
    duplicate in today's section is skipped.

                                                               *:Logpose-done*
:[range]Logpose done
    Mark the task on the current line (or every task in [range]) done.
    `<Plug>(logpose-done)` also works in visual mode.
    In `dirs.inbox` the task is removed and added as `- [x] …` under today
    in `dirs.done`. In any other journal note it's checked off in place
    and logged in DONE with a link back to the note. Non-task lines are
    skipped. The current buffer is edited so |u| undoes it, then saved
    unless it already had unsaved changes.

                                                            *:Logpose-project*
:Logpose project [{name}|none]
    Pin the active project ({name} is slugified), or `none` to go back to
    auto-detection. Without an argument, pick from known projects.

    The active project is, in order: the pinned one, a `projects.paths`
    match, the git repo of the current buffer (or cwd), none. Inside the
    journal there is no project (unless pinned). With a project, meeting
    notes go to `meetings/{project}/`, get `project:` frontmatter, a
    project-scoped series and a `{project}: ` prefix on the daily link.

    `require("logpose").project()` returns the active project.

==============================================================================
TEMPLATES                                                  *logpose-templates*

Templates are looked up in `<root>/<dirs.templates>/<name>.md`, then in the
plugin's `templates/` directory. Shipped: daily, meeting, planning,
refinement, review, retro, 1on1.

Variables: {date} {time} {weekday} {iso_week} {title} {type} {type_label}
{series} {attendees} {project} {sprint}. Unknown variables are left as is. {cursor} marks where
the cursor goes and is removed.

==============================================================================
5. HEALTH                                                     *logpose-health*

`:checkhealth logpose` reports the Neovim version, the resolved journal root
and how it was found, which journal paths exist and the picker in use.
